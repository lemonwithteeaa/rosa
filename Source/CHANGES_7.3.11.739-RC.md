# РОСА 7.3.11.739-RC — восстановление стабильности раздела 8

База релиза: **7.3.11.737-RC**. Код 738 не используется как основа.

## Исправлено

- Восстановлен полноценный Windows x64 GUI build без stripping отладочных PE-секций: размер EXE 20 607 488 байт, 16 PE-секций, штатный `.rsrc` с утверждённой иконкой.
- Геометрия и визуальная разметка раздела 8 не менялись: `buildApprovedRegistryUI` и `layoutApprovedRegistryWorkspace` идентичны стабильной 737 базе.
- У кнопок `СКАЧАТЬ PDF / WORD / EXCEL` раздела 8 теперь собственные уникальные command ID `18771–18773`. Убрано пересечение старых `9771/9772` с командами ручного ввода отказов.
- Двойной щелчок по строке раздела 8 теперь использует фактический `NMITEMACTIVATE.IItem` из события Windows, принудительно закрепляет эту строку и затем открывает отчёт. Это устраняет ситуацию, когда `selectedRow()` ещё возвращал `-1` при быстром двойном щелчке.
- Открытие утверждённого отчёта больше не запускает тяжёлое ленивое обогащение учебных данных в UI-потоке. Просмотр открывается из уже зафиксированного снимка.
- Выгрузка полного отчёта перенесена из UI-потока в отдельный worker. Во время формирования интерфейс не блокируется и не должен «сыпаться»/перерисовываться каскадом.
- DOCX/XLSX/PDF теперь сначала записываются **сразу в конечный файл с реальным расширением**, без обязательного `.tmp`, staging и rename-перехода.
- После записи файл обязательно проверяется: PDF по сигнатуре `%PDF-`, DOCX/XLSX как Office ZIP с обязательными внутренними частями.
- Если первая папка заблокирована корпоративной политикой, РОСА последовательно пробует пользовательские Загрузки/Downloads, Документы, Рабочий стол/OneDrive, внутренний каталог данных РОСА и системный TEMP.
- После успешной записи Проводник открывается с выделенным созданным файлом.
- На время одной выгрузки три кнопки блокируются от повторных нажатий и автоматически восстанавливаются после завершения.
- Для PDF сохранён резервный механизм: если Word/COM не может создать PDF, сформированные резервные DOCX/XLSX не теряются и их пути показываются в сообщении ошибки.
